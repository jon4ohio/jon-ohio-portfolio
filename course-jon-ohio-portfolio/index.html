What this site is (and why it feels fast)

A portfolio can be a pile of pages — or it can be a tiny system. This one is built like a system.

The simplest description

🧭
Pages

Each route is a page file that returns UI (like a menu of rooms).

📚
Content data

The case studies are plain TypeScript objects in lib/ — no database.

🎛️
A theme switch

Light / warm / dark is stored in the browser and applied before React loads.

💡
Key idea

This site is mostly static content. That is why it can be fast and reliable — there are fewer moving parts.

A quick map of the repo

The first big trick: one layout wraps everything

In Next.js, the layout is the always-on frame: navigation at the top, footer at the bottom, and your page in the middle.

CODE 

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" data-theme="warm" suppressHydrationWarning>
      <head>
        <ThemeScript />
      </head>
      <body>
        <Nav />
        <main id="main">{children}</main>
        <Footer />
      </body>
    </html>
  );
}
PLAIN ENGLISH

Define the one wrapper that every page will live inside.

Return a page frame (HTML) that always exists.

Set the language and a default theme on the root element.

Put shared setup in the head, including the theme script.

Start the body (the visible part).

Render the top navigation.

Render the page itself (whatever route you are on) inside main.

Render the footer.

Close up the body and html tags and finish.

🧠
Why this matters for changes

If you want something to appear on every page (like a new link in the nav), you do not edit five pages — you edit components/Nav.tsx once.
